## Tech Stack

- **Frontend**: Angular 17, TypeScript, RxJS
- **Monorepo**: Nx
- **Backend**: Spring Boot
- **Database**: MariaDB, InfluxDB
- **Data Analysis**: JupyterLab, IPython
- **Runtime & Build**: Node.js 20, npm
- **Web API**: BroadcastChannel API
- **Infrastructure**: Nginx
- **Artifact & Package Management**: JFrog Artifactory, npm Package

## 소개

에너지 설비 데이터를 실시간으로 모니터링하고 분석할 수 있도록 구축한 통합 대시보드 플랫폼.

임계치 기반 알림, 데이터 연산 및 시각화, 카드 간 상호작용 기능을 고도화하고 Angular 10 → 17 업그레이드와 JupyterLab·InfluxDB 분석 환경 표준화를 통해 서비스 안정성과 개발·분석 환경을 함께 개선한 프로젝트.

## 주요 개발 내용

- **임계치 기반 실시간 알림 기능 개발**
  - KPI, 게이지, 생키 등 대시보드 카드별 한계치 정보를 기준으로 임계 영역 진입·해제 상태를 감지하고 알림을 생성하도록 구현
  - 사용자별 푸시 알림 권한 및 기능 활성 여부를 관리하여 권한에 따라 알림을 수신할 수 있도록 구성
- **대시보드 데이터 상호작용 및 분석 기능 고도화**
  - 작화 표·차트에서 선택한 데이터를 대시보드 변수와 연계하여 관련 카드 데이터를 동적으로 변경하도록 구현
  - 카드별 Date Picker와 월 Trend 차트를 추가하여 기간별 이력 데이터와 상·하한선을 직관적으로 확인할 수 있도록 개선
- **대시보드 연산 및 시각화 기능 확장**
  - Point, Web Point, RDB 데이터, 상수값을 조합하여 하나의 연산식으로 처리할 수 있는 웹 연산 기능 구현
  - 지도 시각화 차트와 Polar Diagram 등 신규 대시보드 카드 유형을 추가하여 데이터 표현 방식 확장
- **프론트엔드 기술 스택 현대화**
  - 장기간 운영된 Angular 10 기반 레거시 환경을 Angular 17로 업그레이드하여 최신 라이브러리 적용 기반 확보
  - 패키지 간 버전 충돌과 보안 업데이트 대응 문제를 개선하고 프론트엔드 개발 환경 전반을 최신화
- **JupyterLab 데이터 분석 환경 표준화**
  - Notebook마다 반복되던 InfluxDB Connection 초기화 코드를 공통화하여 분석 코드 중복 제거
  - JupyterLab 커널 시작 시 공통 Connection을 자동 초기화하도록 구성하여 사용자별 실행 환경 편차를 최소화
- **로그인 및 사용자 편의 기능 개선**
  - Broadcast 기능을 활용하여 한 브라우저 내 여러 탭의 로그인 상태를 실시간으로 동기화하도록 자동 로그인 기능 구현
  - 로그인 페이지 이미지를 관리자가 등록·변경할 수 있도록 설정 기능 추가

## Angular 프레임워크 10 → 17 버전 업그레이드

- Angular 10 기반 레거시 환경이 장기간 유지되면서 최신 라이브러리 적용 제약, 패키지 간 버전 충돌 및 보안 업데이트 대응의 어려움이 누적되어 **프론트엔드 기술 스택 전반에 대한 업그레이드 필요성 검토**
- 단순 Angular 버전 변경이 아닌 Node.js, Nx, TypeScript, RxJS 등 연관된 개발 생태계의 호환성을 함께 분석하여 **Angular 17을 기준으로 프론트엔드 개발 환경 현대화 방향 수립**
- Angular 주요 버전 간 Breaking Change와 의존성 호환 범위를 확인하며 단계적으로 마이그레이션하고, **Node.js 20 기반으로 Runtime 및 Build 환경을 함께 정비**
- Nx를 `8.5.0 → 18.20.0`으로 업그레이드하면서 기존 Workspace 및 Build 설정을 최신 구조에 맞게 조정하고, Angular·TypeScript·RxJS 등 핵심 의존성 버전을 일관된 기준으로 재구성
- Angular CLI 및 RxJS API 변경으로 발생한 기존 코드 호환성 문제를 분석하고 애플리케이션 코드와 빌드 설정을 수정하여 **기존 기능을 유지하면서 최신 프레임워크 환경으로 안정적으로 전환**
- 프레임워크와 개발 도구의 버전 기준을 함께 정비하여 신규 라이브러리 도입 및 보안 패치 적용이 가능한 기반을 마련하고, **향후 프레임워크 업그레이드 시 발생할 기술 부채와 유지보수 부담을 최소화**
- 결과적으로 장기간 누적된 레거시 프론트엔드 환경을 현대화하고 **빌드 안정성, 패키지 호환성 및 개발환경의 지속적인 유지보수가 가능한 기반 확보**

## JupyterLab 데이터 분석 환경 표준화 및 InfluxDB 연결 자동화

- JupyterLab 기반 데이터 분석 과정에서 Notebook마다 InfluxDB Connection 초기화 코드가 반복 작성되고, 사용자별 접속 설정 차이로 인해 **분석 코드 중복과 실행 환경 편차가 발생하는 문제** 확인
- 분석 로직과 DB 연결 설정의 책임을 분리하기 위해 **JupyterLab 커널 시작 시 공통 Connection을 자동으로 초기화하는 실행 구조로 개선**
- IPython `startup` 스크립트를 활용하여 커널 기동 시 InfluxDB Connection 객체를 생성하고 전역 Namespace에 등록함으로써, Notebook에서 별도의 연결 코드 없이 즉시 데이터 조회가 가능하도록 구성
- DB Endpoint 및 인증 정보를 `.ini` 기반 설정으로 외부화하여 Notebook 코드에서 접속 정보를 제거하고, **환경별 설정 변경과 Connection 관리가 공통 영역에서 이루어지도록 표준화**
- 공통 Connection 초기화 로직을 중앙화하여 Notebook별 중복 코드를 제거하고, 신규 분석 Notebook에서도 동일한 방식으로 데이터 접근이 가능하도록 개발 환경 일관성 확보
- 결과적으로 **분석 코드와 인프라 설정의 결합도를 낮추고, 데이터 조회 준비 과정을 단순화하여 JupyterLab 기반 분석 환경의 사용성과 유지보수성을 개선**

## 브라우저 멀티탭 인증 상태 동기화 구조 설계

- 동일 브라우저에서 여러 탭을 동시에 사용하는 환경에서 로그인·로그아웃 및 인증 만료 상태가 탭별로 독립적으로 관리되어, **사용자 인증 상태가 서로 다르게 유지되는 문제** 발생
- 각 탭에서 개별적으로 인증 상태를 판단하는 방식 대신, 브라우저 내부에서 인증 이벤트를 공유할 수 있도록 **탭 간 이벤트 기반 세션 동기화 구조로 재설계**
- `BroadcastChannel API`를 활용하여 로그인, 로그아웃, 인증 만료 등 주요 인증 이벤트를 브라우저 내 모든 탭에 전달하고, 각 탭이 동일한 세션 상태를 유지하도록 구성
- 신규 탭 또는 새로고침된 애플리케이션이 기존 인증 상태를 인지할 수 있도록 초기화 과정에서 다른 탭의 세션 상태를 요청·응답하는 **세션 상태 공유 흐름 구현**
- 로그아웃 및 인증 만료 발생 시 해당 이벤트를 전체 탭으로 전파하여 특정 탭에 이전 인증 정보가 남지 않도록 하고, **사용자 인증 lifecycle을 브라우저 전체에서 일관되게 관리**
- 탭 간 직접적인 상태 의존성을 최소화하고 인증 이벤트를 기준으로 동작하도록 구성하여 향후 인증 정책 변경 및 추가 이벤트 확장에도 대응 가능한 구조 확보
- 결과적으로 **멀티탭 환경에서 발생하던 인증 상태 불일치를 제거하고 로그인·로그아웃 동작의 일관성과 사용자 경험을 개선**

## Nx Monorepo 기반 프론트엔드 공통 아키텍처 및 라이브러리 표준화

- 여러 SCADA 애플리케이션에서 인증, 세션 관리, 공통 UI 기능이 개별적으로 구현되어 **동일 기능의 중복 개발과 애플리케이션별 구현 편차가 발생하는 구조적 문제** 확인
- 애플리케이션별로 공통 기능을 관리하는 방식에서 벗어나기 위해 **Nx Monorepo를 기준으로 공통 영역과 애플리케이션 영역의 책임을 분리하는 프론트엔드 구조로 재설계**
- 인증, 세션 관리, 공통 UI 등 재사용 가능한 기능을 Nx `lib` 단위로 분리하고, 애플리케이션이 필요한 기능을 명시적으로 참조하도록 구성하여 **모듈 간 의존 관계를 정리**
- LIPS 및 SCADA 애플리케이션에서 반복적으로 사용되는 기능을 공통 라이브러리로 통합하여 개별 프로젝트의 중복 구현을 제거하고, 기능 변경 시 공통 영역을 중심으로 관리할 수 있도록 구조 개선
- 애플리케이션 내부에서만 사용하는 라이브러리와 여러 프로젝트에서 공유해야 하는 기능의 배포 범위를 구분하고, 공용 기능은 **npm Package 형태로 제공하여 프로젝트 간 재사용이 가능한 배포 구조 구축**
- Nx Workspace를 기준으로 공통 라이브러리의 위치와 역할을 정형화하여 신규 애플리케이션이 추가되더라도 동일한 구조와 개발 방식을 적용할 수 있도록 **프론트엔드 모듈화 기준 표준화**
- 결과적으로 **중복 코드 감소, 공통 기능의 일관성 확보 및 애플리케이션 간 의존성 관리 개선을 통해 다중 프론트엔드 프로젝트의 유지보수성과 확장성 향상**

## SCADA UI/UX 개편 및 프론트엔드 스타일 아키텍처 재정비

- SCADA 시스템의 UI/UX 3.0 전면 개편 과정에서 다수 화면과 모듈이 하나의 공통 CSS에 의존하면서 **스타일 변경 시 예상하지 못한 화면까지 영향을 받는 높은 결합도와 유지보수 문제** 확인
- UI 개편을 단순한 화면 디자인 변경으로 처리하지 않고, 향후 기능 확장과 지속적인 UI 변경을 고려하여 **공통 스타일과 모듈별 스타일의 책임 범위를 재정의하는 방향으로 스타일 구조 재설계**
- 전역으로 관리할 색상, Typography, Layout 등 공통 디자인 요소와 개별 화면에서만 필요한 스타일을 구분하고, **기능 및 모듈 단위로 스타일을 독립적으로 관리할 수 있도록 구조 분리**
- 기존 공통 CSS에 누적되어 있던 화면별 스타일 의존성을 단계적으로 제거하여 특정 기능의 UI 변경이 다른 모듈에 영향을 주지 않도록 **스타일 영향 범위를 모듈 내부로 제한**
- 반복적으로 사용되는 UI 요소는 공통 영역에서 일관되게 관리하면서 개별 기능의 스타일은 독립적으로 확장할 수 있도록 구성하여 **공통화와 모듈 독립성 간의 균형을 고려한 스타일 관리 기준 정립**
- UI/UX 3.0 적용과 함께 기존 스타일 구조의 기술 부채를 정리하여 신규 화면 및 기능 추가 시 기존 CSS에 대한 의존도를 낮추고, 동일한 스타일 관리 원칙을 적용할 수 있는 기반 마련
- 결과적으로 **스타일 충돌과 변경 영향 범위를 줄이고 화면 일관성, 유지보수성 및 향후 UI 확장성을 함께 확보**
